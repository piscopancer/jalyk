- шаблоны для полей и документов. Шаблон — объект `{ label, value }`, где `value` либо статическое значение, либо колбэк, считаемый на клиенте в момент клика (`() => new Date()` для текущего времени). Подпись всегда в `label`, в меню не будет `anonymous`. Сериализации нет — конфиг объявляется на клиенте в студии, функции живые. Шаблоны строго типизированы относительно значения. Два уровня: на поле — объявляются в фабрике (`text().templates([...])`), тип `value` выводится из типа поля (дата-шаблон к строке не компилируется); на документ — возвращают строго типизированный объект по полям документа. Охват — все виды полей, включая объекты и массивы объектов (для них `value` это вложенный объект / массив объектов нужной формы). UI поля — штатный `DropdownMenuSub` shadcn в «троеточии» хедера: меню по клику, подменю «Шаблоны» по наведению, самописного не нужно. UI документа — в меню «статус документа» рядом с просмотром JSON. Применение: значение из шаблона течёт через ту же валидацию, что и ручной ввод (невалидное подсветится аномалией, но впишется); при конфликте с заполненными полями — диалог подтверждения.

  Сделано (этап 3, async-шаблоны): фабрика `defineTemplate` (query.ts) по образцу `defineReference` — обычная функция без хуков; колбэк получает `ctx = { documentId, client }`, где `documentId` это id уже сохранённого документа, а `client` — императивный async-клиент (`AsyncClientOf`, зеркало хук-клиента студии без React, поверх runFindMany). `FieldTemplate<V>` расширен до `value: V | ((ctx) => V | Promise<V>)` с обратной совместимостью с синхронными шаблонами. `defineTemplate<V>` берёт `V` через `NoInfer` сверху (из опции `templates` поля), а не из тела колбэка — иначе вывод тела через ctx.client замкнулся бы на config (цикл). Тип ctx.client типизируется НЕ от typeof config, а от ручного реестра карт полей `TemplateDocumentRegistry` (declare module, ключ → карта полей читаемого документа через `(typeof xDoc)['fields']`; синтезируется конфиг + `& AnyConfig`, иначе DocumentType схлопывается в string). Регистрировать можно ВСЕ типы документов — индексация Client по ключу ленива, поэтому шаблон одного документа может читать любой другой зарегистрированный тип. Единственное неустранимое ограничение — истинная самоссылка: шаблон не может читать СВОЙ же тип документа (значение зависело бы от полностью вычисленного типа самого себя — фундаментальный цикл TS). Демо: шаблон названия альбома «По первой группе» читает band; зарегистрированы все четыре документа. Студия строит рантайм-клиент через `createAsyncClient(deps, config)` и кладёт в ctx с кастом на границе типов. UX унифицирован: любой клик (sync и async) сразу открывает диалог с лоадером, по резолву — дифф «Сейчас/Станет», при ошибке — ошибка в том же диалоге, запись по подтверждению. Открытый вопрос: что в ctx.documentId для нового, ещё не сохранённого документа. Типизация: `defineTemplate` выводит V из тела/значения колбэка (без NoInfer и без явного дженерика — `defineTemplate({...})` достаточно для любого поля, включая строки и select), ограничение поля проверяет соответствие; цикл разорван не этим, а ленивой индексацией Client по ключу.
  Реестр объединён (этап 4): два declare-module-реестра (`DocumentRegistry` ключ→true для `to` и `TemplateDocumentRegistry` ключ→карта полей для шаблонов) слиты в один `SchemaRegistry` (field.ts), ключ → определение документа (`{ band: typeof bandDoc; ... }`). `DocumentTypeKey` = `keyof SchemaRegistry` (берёт только имена членов, значения не вычисляет — ссылка documents → defineReference → keyof не циклит); шаблоны индексируют `SchemaRegistry[K]['fields']` лениво по ключу. Перечислять документы в declare module теперь нужно один раз. Намеренно интерфейс с отдельными членами, а НЕ `typeof documents`: единый const вычисляется целиком, втягивая документ с шаблоном, и тип замыкается сам на себя (проверено — ломает проекции студии в `{}`). `keyof typeof documents` / `types: keyof typeof documents` тоже циклят — ключи нельзя вывести из самого const.
