## Создание/редактирование документа в поле ссылки инлайн

Ядро навигации (линейный стек сегментов, `definePathSegment`, `useNavStack`, переходы `open.*`/`PathSegmentLink`) уже есть — см. Архив. Эта задача надстраивается над ним: поле ссылки должно само открывать сегменты пути для создания/редактирования цели.

создавать документ прямо в поле ссылки на документ. так можно делать цепочку бесконечно (создал документ в просмотре всех документов, когда выбирал значение для reference - открылась форма, внутри у создаваемого документа еще есть поле-ссылка - и так по кругу создаются дальше и дальше сегменты просмотра с документами, точно так же и для реактирования, внутри reference ведь они так же создают сегменты пути), открывается новый сегмент.

Временных сегментов не будет — персиститься будут все сегменты как обычно. У каждого сегмента сверху появляется хедер с названием сегмента и кнопкой-крестиком у правого края. Закрыть (х) можно любой сегмент, кроме корневого.

кстати помимо редактирования инлайн, документ развернуть в его превью, если он был выбран. благодаря этому когда просматриваешь превью можно не нажимать кнопку около превью "редактировать" чтоы увидеть поля в следующем сегменте, а просто нажать на шеврон вниз и он откроет форму. причем форма превью что для шеврона вниз что для редактирования будет браться из конфига (вроде definePreview или как оно там)

Чего не хватает в ядре под эту задачу (надо доделать здесь):

- хедер сегмента: у каждого сегмента сверху строка с названием и крестиком справа; крестик зовёт `close` текущего уровня. У корневого сегмента крестика нет (его нельзя закрыть);
- открытие сегментов из поля, а не только из view сегмента: `usePathSegmentNav` (go/close) доступен лишь внутри `view`, а поле ссылки рендерится глубоко в форме документа-сегмента — go там уже работает (контекст сегмента прокинут на любую глубину), но нужны типобезопасные переходы в «документы/документ» того типа, на который ссылается reference, плюс ветка «создать новый» против «открыть существующий»;
- разворот превью в форму по шеврону: и шеврон, и кнопка «редактировать» открывают один и тот же сегмент документа, форма берётся из конфига (`definePreview`/аналог).

# Баги

- серверная часть рассогласования (api/web): на отдаче клиентскому запросу документ со структурно-сломанным полем (conformancePaths непуст) режется целиком, а безобидные неизвестные поля просто срезаются. Сейчас в студии всё видно и чинится, но сам срез на выдаче ещё не реализован.

- здоровье контента: перед тем как правка схемы (переименование/удаление поля, изменение predefined) уедет, показать в студии, сколько живых документов она уронит из клиентской выдачи (через conformancePaths по всем документам типа) — иначе массовый обвал контента видно не в студии, а по пропаже на сайте.

# Архив

## Поле-картинка: кнопки источников и «Убрать» (сделано)

Подписи и иконки кнопок поля-картинки приведены к набору: «Загрузить» (`UploadIcon`, всегда — заливка с диска), «Выбрать» (`ImagesIcon`, всегда — из библиотеки, бывшее «Смотреть все») и «Убрать» (`XIcon`, ghost, приглушённая, отодвинута через `ml-auto`, только при наличии обложки, бывшее «Удалить»). Слово «Заменить» убрано: кнопки-источники статичны по источнику, а не по состоянию. Корзину не используем — кнопка лишь отвязывает ссылку (`handle.set(null)`), файл остаётся в библиотеке, поэтому крестик честнее. Реализация: `packages/studio/src/fields/image.tsx`.

## Навигация — ядро (сделано)

Линейный стек сегментов с персистом в localStorage и восстановлением после перезагрузки, как папки в ОС. Путь — одна линейная цепочка (на каждом уровне один открытый потомок); колонки и слои — два рендера одного стека. Сегменты объявляются статическим деревом `definePathSegment` (`view` + `children`) с типизированными переходами `open.<child>(params)` и `PathSegmentLink`. Путь хранится только в localStorage по ключу `navigation.key` (без URL); восстановление идёт по дереву определений, неизвестное звено в середине обрезает путь (структурно). Реализация: `packages/studio/src/data/navigation.tsx`, встроенное дерево `views/segments.tsx`, `MillerView`/`LayerView` переписаны поверх `useNavStack`, проп `<Studio navigation>`. Кастомный пример с кнопкой «Джарибек» (панель хранилища) — в `apps/test-client`.
