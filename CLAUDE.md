# Jalyk

## Запуск

Все сервисы поднимаются из корня командой `pnpm dev`: она через `predev` запускает Postgres (`docker compose up -d --wait`), а затем лаунчер `scripts/dev.ts` раскрывает флаги/пресеты в состояния подсистем и запускает `turbo run dev` со всеми приложениями.

Состояние каждой подсистемы (БД, авторизация, хранилище) выбирается флагами запуска, а не правкой `.env`. Без флагов `pnpm dev` — всё локальное. Флаги: `--db=local|prod|empty|many|demo`, `--storage=files|s3|memory`, `--auth=local|prod`; можно комбинировать. Есть именованные пресеты первым позиционным аргументом (`pnpm dev staging`), которые флаги точечно перебивают. Сид-состояния БД (`empty`/`many`/`demo`) лаунчер засевает в базу `jalyk_seed` один раз перед стартом. Лаунчер кладёт выбор в `JALYK_DB_STATE` / `JALYK_STORAGE_STATE` / `JALYK_AUTH_STATE` в окружении дочерних процессов; напрямую `pnpm turbo run dev` теперь не запускать — без этих переменных приложения падают с `ConfigError`. Базой отдельно управляют `pnpm db:up`, `pnpm db:down` и `pnpm db:reset`.

Приложения и порты: web — `:3000`, api — `:3001`, test-client (песочница студии) — `:3002`.

## Иконки

Иконки из `lucide-react` всегда импортировать под именем с постфиксом `Icon`, чтобы не путать их с обычными значениями и компонентами. lucide-react экспортирует каждую иконку и в варианте с суффиксом, поэтому имя берётся напрямую, без алиаса `as`: `import { UsersIcon, Disc3Icon } from "lucide-react"`.

## Адреса при включённом VPN

У пользователя постоянно включён VPN, из-за которого `localhost` не открывается. Обращаться к сервисам нужно по локальному LAN-адресу машины, который Vite печатает в блоке `Network` при старте (например `http://192.168.1.192:3000`), а не по `localhost`. Конкретный IP может меняться между сессиями — всегда брать актуальный из вывода `Network`. Это касается и любых проверок через `curl`/браузер: не использовать `localhost` и `127.0.0.1`, а подставлять текущий LAN-IP.
